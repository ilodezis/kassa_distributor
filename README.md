# Kassa Distribution Tool

Инструмент для распределения касс между менеджерами сопровождения. Берёт выгрузку из Excel, раскидывает кассы по людям через модель со штрафами (cost function) и даёт UI для управления командой.

## Возможности

- Балансировка по менеджерам: выравнивание общего количества касс (допуск ±5) и тарифных периодов 1/3/12 месяцев (допуск ±3).
- Редактор менеджеров в UI: роли (`is_support`), индивидуальные лимиты (`cap`), массовое редактирование через multi-select.
- Настройки команды хранятся в `managers.json`, не в коде.
- Минимум миграций: текущие привязки сохраняются где возможно, оплаченные кассы не трогаются.
- Экспорт в Excel (итоговое распределение, summary, лог перемещений, лог проверок) и график результата.

## Правила распределения

1. **Заморозка оплат.** Если `Оплачен ИНН = 1` и касса уже на менеджере сопровождения — не перемещается.
2. **Внешний пул.** Кассы на менеджерах не из сопровождения (оплаченные и нет) принудительно переносятся в сопровождение.
3. **Индивидуальные лимиты.** Кассы равномерно распределяются между менеджерами с лимитом (до их cap) и без лимита.
4. **Консервативный ребаланс.** Неоплаченные кассы внутри сопровождения двигаются по минимуму — только чтобы выровнять таргеты и доли тарифов.

## Как работает алгоритм

Это не точная оптимизация (не ILP/венгерский алгоритм), а жадный greedy-проход плюс локальный поиск улучшений поверх штрафной функции. Глобальный минимум не гарантирован, зато результат предсказуем и считается мгновенно даже на тысячах строк.

**1. Расчёт таргетов.** Для каждого support-менеджера считается справедливая доля: `всего касс / число менеджеров`, обрезанная по `cap`, если он задан, и не ниже уже зафиксированных (paid) касс. Дробные остатки округляются методом наибольшего остатка (largest remainder), чтобы сумма таргетов точно совпала с общим числом касс. Таргет по каждому тарифу (1/3/12) внутри менеджера считается так же — от глобальной доли этого тарифа во всей выгрузке.

**2. Штрафная функция (cost function).** Для total и для каждого тарифа: `штраф = (превышение допуска)²` — допуск ±5 по total, ±3 по тарифу. Превышение `cap + допуск` — отдельный штраф на порядки больше остальных, по сути запрет. Сумма штрафов по всем менеджерам — то, что алгоритм минимизирует.

**3. Раскидка внешних касс.** Кассы с не-support менеджеров сортируются от самого редкого тарифа к самому частому (чтобы под конец не остаться без вариантов), и каждая по очереди уходит тому менеджеру, у которого её добавление даёт наименьший прирост штрафа. Выбор жадный, без отката назад — уже назначенная касса не пересматривается.

**4. Внутренний ребаланс.** Затрагивает только неоплаченные кассы внутри support (paid — заморожены правилом 1). На каждой итерации ищется одно перемещение донор → получатель, которое сильнее всего снижает суммарный штраф; повторное обращение к одному донору штрафуется отдельно, чтобы нагрузка не спихивалась на одного-двух человек. Цикл останавливается, как только ни один ход не улучшает штраф (локальный минимум), либо после 5000 итераций.

## Установка

Python 3.10+.

```bash
pip install -r requirements.txt
```

Для UI нужен `tkinter`: на Windows/macOS ставится вместе с Python, на Linux — пакет `python3-tk`.

## Запуск

```bash
python app.py
```

## Формат входного Excel

Обязательные колонки:

| Колонка | Значения |
|---|---|
| `Менеджер` | ФИО текущего менеджера, на котором висит касса |
| `Тариф` | `1`, `3` или `12` (месяцев) |
| `Оплачен ИНН` | `1` — оплачена, `0` — нет |

Остальные колонки выгрузки программа не трогает и переносит в результат как есть.

## Как пользоваться

1. Загрузи Excel с исходными кассами.
2. Нажми «Подтянуть менеджеров из Excel» — новые имена попадут в базу. Во вкладке «Менеджеры» отметь участников сопровождения и задай лимиты (cap), если нужно. Сохрани `managers.json`.
3. Запусти распределение.
4. Проверь вкладки Summary, Moves, Checks и Chart.
5. Сохрани результат в Excel.

Результат — файл с листами `result` (исходные данные + колонка `Новый менеджер`), `summary`, `moves` (лог перемещений) и `checks` (лог проверок на логические ошибки).

## managers.json

Список менеджеров с ролью и лимитом, редактируется через UI или руками:

```json
{
  "version": 1,
  "managers": [
    { "name": "Иванов Иван Иванович", "is_support": true, "has_cap": false, "cap": null },
    { "name": "Петров Пётр Петрович", "is_support": true, "has_cap": true, "cap": 150 }
  ]
}
```

- `is_support` — участвует ли менеджер в распределении (кассы не-support менеджеров всегда переносятся в пул).
- `has_cap` / `cap` — жёсткий потолок по количеству касс на менеджера.
